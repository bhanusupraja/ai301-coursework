# Rubric: is this pull request ready to submit?

Read the whole package (issue, repo facts, plan context, title, description, commits, diff, test evidence) before grading. Every check judges the thing itself: the diff against the plan, the evidence against the plan's test plan, the description against the diff. Never grade length, polish or headings. A PR that honestly discloses a shortfall can be ready.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The diff's changed files and hunks, read against the plan's in-scope and not-in-scope statements, files list and approach (plus any deviation note). | Every changed file and hunk is something the plan (or a deviation note) says to change, and every planned change is in the diff or its absence is disclosed in a deviation note or the description. Fail if the diff does more than the plan (an extra option or flag, a rewrite, a rename pass, a file the plan never names, something the plan scopes out), or does less with no disclosure. A deliberately deferred part that the plan or description says is deferred passes. | required |
| description-matches-diff | Each claim in the description ("implements the plan exactly", "no functional changes outside X", "docs updated", the Changes list), read against the diff. | Every load-bearing claim the description makes is true of the diff: nothing it says was delivered (a fix, a docs update, a test, a flag) is missing from the diff, and it does not say "exactly as planned" or "nothing else changed" over a diff that contradicts that. Fail if the description claims a deliverable the diff does not contain, or hides a change the diff contains. A minor imprecision that does not change what was delivered (a loose count of test cases, "one function" when a small helper rides along, wording) does not fail. | required |
| evidence-decisive | The test evidence, read against the plan's test plan and the reproduction's own steps. | The evidence re-runs the plan's repro or test plan on the path the fix changes and shows an observable before and after (an output, value, exit code or behavior that changes), covering the failure mode the issue's trigger shows, and any further failure mode the plan's test plan names is at least addressed with a stated outcome or a test (a named mode left silent fails; a secondary mode reported in a sentence beside a shown primary before and after does not). Fail if it is only "tested locally" or "tests pass" with no named behavior, if it exercises a path the fix does not change (a control case instead of the trigger), or if the before or after is never shown. A repro the evidence honestly says it could not run, with the reason, is judged by what it does show. | required |
| repo-checks-run | The test evidence and the repo-facts block, read against the checks the repo's PR template or contribution docs list (tests, lint, typecheck, changelog or i18n steps). | The evidence or the description states that the checks the repo asks for were run, with their outcome (pass, or a failure reported honestly with the reason). A stated result, such as "312 tests pass, fmt and clippy clean", counts without pasted output. Fail if the tests for the changed code were never run, if a required check is not mentioned as run at all, or if a claimed result contradicts the evidence shown. | required |
| diff-clean | The unified diff and the commit list, scanned for what does not belong to the fix. | The diff has no debris: no debug prints or leftover logging, no commented-out code, no dead or unused functions or imports added, no formatting-only or re-indent churn, no unrelated edits mixed in. The fix is visible on its own. Fail if any of these is present, even when the core fix is right. Mechanical churn around a right fix still fails. | required |
| standards-met | The repo-facts block's PR-template asks and contribution policy (including any AI-use rule), read against the description and the diff. | Every section or item the repo's template and policy require is present with real content (for example an issue reference, a required checklist, a changelog or whatsnew entry the diff must contain), and if the policy requires AI-use disclosure, the description discloses it (tool and extent as asked). If the repo states no such ask, pass. A rule that text must be in the author's own words is not a disclosure requirement: pass if it reads as plain human voice. Fail if a stated ask is visibly ignored. | required |

## Verdict rule

Accept only if every check passes. All checks are required, and there are no preferred checks. A check graded `unclear` counts as `fail`: a PR that cannot be verified from the package is not ready to submit. Reject otherwise. Quote the deciding evidence for each failed check.
